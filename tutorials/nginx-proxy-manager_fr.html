Configuration de Nginx Proxy Manager (NPM)

3. Nginx Proxy Manager (NPM)

Dans ce chapitre, nous allons configurer l'accès externe aux services (Lightning Terminal, LNbits, Cashu et Orchard) en utilisant Nginx Proxy Manager, qui agit comme proxy inverse et gestionnaire de certificats SSL.

Accès initial

L'accès initial au conteneur Nginx Proxy Manager (NPM) se fait via HTTP en utilisant le port 81. Dans notre exemple, nous y accéderons via l'URL http://npm.cashu4community.xyz:81. À l'étape suivante, nous modifierons cette configuration pour éviter les risques de sécurité.

Le conteneur est déjà préconfiguré, donc aucune création d'utilisateur n'est requise lors du premier démarrage.

Image 1 : Page de connexion Nginx Proxy Manager.

  1. Utilisateur changeme@domain.com
  2. Mot de passe ch4ng3m3*-
  3. Nous appuyons sur Entrée ou cliquons sur Sign in.

Après la connexion, nous accédons au tableau de bord du service NPM.

Image 2 : Tableau de bord NPM.

  1. Nous accédons au panneau Proxy Host.

3.1 Création d'un proxy host pour NPM

Comme nous avons pu l'observer, l'accès à NPM se fait via HTTP (protocole non sécurisé) et par le port 81, ce qui rend notre service vulnérable aux attaques. Pour résoudre ce problème, nous allons créer un Proxy Host pour NPM lui-même afin de pouvoir opérer sur HTTPS.

Image 3 : Ajouter un Proxy Host.

  1. Nous ajoutons un Proxy Host.

Image 4 : Options du Proxy Host.

  1. Domain Names : dans ce champ, on saisit le nom de domaine que l'application aura sur Internet. Comme nous configurons l'accès à NPM, nous utiliserons le domaine npm.cashu4community.xyz.
  2. Scheme : le schéma est le protocole utilisé par NPM pour communiquer avec l'application qui tourne dans le conteneur ; il peut être http ou https. Pour NPM, nous le laissons en http.
  3. Forward Hostname / IP : c'est simplement le nom d'hôte. Comme il s'agit d'un conteneur Docker, il est préférable d'utiliser le nom du service. Comme nous configurons NPM, nous utiliserons npm. La liste complète des services se trouve à la fin de la section Premiers Pas.
  4. Forward Port : c'est le port sur lequel l'application tourne en interne dans le conteneur Docker. NPM utilise le port 81. La liste des ports se trouve à la fin de ce chapitre.
  5. Options : nous activons toutes les options pour améliorer la sécurité et la fonctionnalité de l'application.

Image 5 : Options SSL du Proxy Host.

  1. Nous nous positionnons dans l'onglet SSL.
  2. Nous sélectionnons dans le menu déroulant l'option Request a new Certificate.
  3. Nous activons les options Force SSL, HTTP/2 Support et HSTS Enabled.
  4. Nous sauvegardons les modifications.

Après avoir sauvegardé les modifications, nous pouvons voir l'enregistrement NPM dans le panneau de la section Proxy Host.

Image 6 : Enregistrement du service NPM dans le panneau Proxy Host.

Important : Pour créer le certificat numérique, NPM vérifie que le domaine DNS existe. S'il n'existe pas, le processus échouera.

Image 7 : Proxy Host correctement configuré.

Avec NPM déjà configuré pour un accès sécurisé via HTTPS, nous nous déconnectons et nous reconnectons pour continuer avec les autres configurations.

Image 8 : Déconnexion — Menu utilisateur.

  1. Nous nous déconnectons.

Comme mentionné au début de ce chapitre, le service NPM est livré préconfiguré avec un compte utilisateur générique. Pour éviter les accès non désirés à notre infrastructure, il est obligatoire de changer ce compte. Pour ce faire, nous accédons au menu utilisateur.

  1. Nous cliquons sur Edit Profile pour modifier l'adresse e-mail que nous utilisons pour nous connecter.

Image 11 : Modification du nom d'utilisateur et de l'adresse e-mail.

  1. Nous mettons à jour le champ Email address avec notre adresse e-mail.
  2. Nous sauvegardons les modifications.

Image 12 : Menu utilisateur — Changement de mot de passe.

  1. Nous cliquons sur Change Password pour modifier le mot de passe actuel.

Image 13 : Changement du mot de passe de l'utilisateur actuel.

  1. Nous saisissons le mot de passe actuel.
  2. Nous saisissons le nouveau mot de passe et le confirmons.
  3. Nous sauvegardons les modifications.

Image 14 : Menu utilisateur — Authentification à deux facteurs.

  1. Nous cliquons sur Two-Factor Auth (recommandé pour une couche de sécurité supplémentaire).

Image 15 : Activation du 2FA dans NPM.

  1. Nous cliquons sur le bouton pour activer l'authentification à deux facteurs.

Image 16 : Activation du 2FA via QR avec code de vérification.

  1. Nous scannons le QR avec l'application 2FA Authenticator ; nous pouvons également utiliser d'autres applications comme Authy.
  2. Si le scan du QR n'est pas possible, nous copions le code directement dans l'application 2FA.
  3. Nous collons le code à 6 chiffres généré par l'application 2FA.
  4. Nous vérifions.

Si la vérification échoue, c'est peut-être parce que le code à 6 chiffres a expiré ; nous pouvons réessayer. L'étape suivante nous affichera les codes de récupération nécessaires au cas où nous perdrions le code 2FA ou si l'application est désinstallée.

Image 17 : Codes de récupération 2FA.

  1. Nous copions les codes de récupération et confirmons.

Image 18 : Options 2FA.

  1. Nous cliquons ici si nous voulons désactiver le 2FA.
  2. Nous cliquons ici si nous voulons de nouveaux codes de récupération.

3.4 Suppression de l'accès à NPM via le port 81

Nous avons confirmé l'accès sécurisé à NPM et mis à jour les identifiants du compte administrateur. Nous allons maintenant désactiver l'accès à NPM via le port 81. Pour cela, nous éditons le fichier docker-compose.yml situé dans cashu4cs-deploy.

nano docker-compose.yml

Nous recherchons le service NPM qui commence par la ligne npm: et supprimons la ligne - '81:81' de ports:

 npm:
    image: jc21/nginx-proxy-manager:latest
    container_name: nginx_proxy_manager
    restart: unless-stopped
    ports:
      - '80:80'
      - '443:443'
      - '81:81'
    environment:
      - DB_SQLITE_FILE:"/data/database.sqlite"
      - DISABLE_IPV6:'true'
    volumes:
      - ./app-data/npm/data:/data
      - ./app-data/npm/letsencrypt:/etc/letsencrypt

Service NPM sans le port 81 :

 npm:
    image: jc21/nginx-proxy-manager:latest
    container_name: nginx_proxy_manager
    restart: unless-stopped
    ports:
      - '80:80'
      - '443:443'
    environment:
      - DB_SQLITE_FILE:"/data/database.sqlite"
      - DISABLE_IPV6:'true'
    volumes:
      - ./app-data/npm/data:/data
      - ./app-data/npm/letsencrypt:/etc/letsencrypt

Nous sauvegardons et quittons le fichier ctrl+s et ctrl+x.

Enfin, nous recréons le conteneur du service NPM pour que les modifications prennent effet :

docker-compose up --force-recreate npm -d
