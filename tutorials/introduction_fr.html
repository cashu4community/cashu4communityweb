Introduction

0. Introduction

À quoi servent ces tutoriels ?

Cette série de tutoriels guide les communautés militantes et les organisations sous pression autoritaire dans le déploiement d'une infrastructure complète de paiements privés et résistants à la censure, basée sur Bitcoin, Lightning Network et Cashu.

En complétant tous les tutoriels, votre communauté disposera d'un système de paiement souverain : sans gardiens, sans surveillance financière et capable de fonctionner même dans des conditions réseau défavorables.

Comment utiliser l'infrastructure

L'infrastructure est composée de plusieurs services qui travaillent ensemble. Voici la fonction de chaque service et sa place dans l'utilisation quotidienne :

Lightning Network Daemon (LND)

C'est le nœud de base de l'infrastructure. Il se connecte au réseau Lightning et gère les canaux de paiement. Tous les paiements en sats qui entrent et sortent de l'infrastructure passent par LND. La communauté n'interagit pas directement avec lui, mais c'est le moteur qui rend possibles la plupart des autres services.

LNbits

C'est la couche de gestion des fonds. Elle permet de créer plusieurs portefeuilles sur le solde du nœud LND, en segmentant l'argent par objectif (commissions, réserves, paiements de services). L'administrateur de la communauté l'utilise pour contrôler qui a accès à quels fonds et pour surveiller les paiements.

Mint Cashu (Nutshell)

C'est le cœur du système de confidentialité. Le Mint émet des tokens Cashu (ecash) adossés à des sats Lightning. Les membres de la communauté reçoivent et envoient ces tokens sans laisser de trace sur la blockchain. Les transactions entre membres sont complètement privées, même pour l'opérateur du Mint.

Lightning Terminal (LIT)

C'est le tableau de bord du nœud Lightning. L'administrateur l'utilise pour gérer la liquidité des canaux (Loop In/Out), vérifier l'état du nœud et se connecter à distance et en toute sécurité via Lightning Node Connect.

Nginx Proxy Manager (NPM)

C'est la porte d'entrée sécurisée vers tous les services. Il gère les certificats SSL et permet d'accéder à chaque outil via son propre sous-domaine (par exemple : lnbits.votredomaine.com, mint.votredomaine.com). Sans lui, les services ne seraient pas accessibles depuis Internet de manière sécurisée.

Orchard

C'est le panneau d'administration du Mint Cashu. Il permet à l'administrateur de configurer le Mint, de vérifier l'état de la base de données, de gérer les keysets et de surveiller l'activité sans avoir besoin d'accéder à la ligne de commande.

Tor

Ajoute une couche supplémentaire de confidentialité en acheminant les connexions du nœud LND à travers le réseau Tor. Cela masque la véritable adresse IP du serveur et rend la surveillance ou le blocage de l'infrastructure plus difficile.

Prérequis

Avant de commencer avec le Tutoriel 1, assurez-vous de disposer des éléments suivants :

Nom de domaine

Vous avez besoin d'un nom de domaine DNS valide (par exemple : votredomaine.com) qui supporte la création de sous-domaines. Chaque service de l'infrastructure est publié sous son propre sous-domaine :

  • lnbits.votredomaine.com
  • mint.votredomaine.com
  • orchard.votredomaine.com
  • npm.votredomaine.com
  • lit.votredomaine.com

Vous pouvez obtenir un nom de domaine sur Namecheap ou GoDaddy. Le Nginx Proxy Manager (Tutoriel 3) se chargera de gérer les certificats SSL automatiquement.

Serveur VPS

Vous avez besoin d'un serveur privé virtuel (VPS) avec le système d'exploitation Debian ou Ubuntu. Les plans Hostinger suivants sont recommandés (avec réduction via les liens du projet) :

  • VPS KVM1 — pour usage de base
  • VPS KVM2 — recommandé pour la production

Connaissances de base

Les tutoriels sont conçus pour être suivis étape par étape, mais il est utile d'avoir une familiarité de base avec :

  • Terminal Linux (commandes de base : ls, cd, nano)
  • Gestion DNS (créer des enregistrements A pour les sous-domaines)
  • Docker (utile mais non indispensable ; toutes les commandes sont expliquées étape par étape)
Important : Les tutoriels doivent être suivis dans l'ordre. Chaque service dépend des précédents pour fonctionner correctement.
