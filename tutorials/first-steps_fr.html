Premiers Pas

1. Premiers Pas

Dans ce chapitre, nous préparons l'environnement de base sur lequel toute l'infrastructure sera construite. Avant d'exécuter toute commande, nous vérifions que nous disposons des prérequis suivants :

1.1 Prérequis

  • Serveur VPS avec système d'exploitation Debian/Ubuntu (disponibles avec réduction via les liens Hostinger suivants : VPS KVM1 et VPS KVM2, nous recommandons le KVM2 pour la production).
  • Docker 26.0+.
  • Docker Compose 2.0+.
  • Nom de domaine DNS valide pour publier les services sur Internet (disponible sur Namecheap, Hostinger ou GoDaddy ; Namecheap et Hostinger acceptent les paiements en Bitcoin).

1.3 Installation des prérequis

1.3.1 Installation de Docker et Docker Compose

La plupart des VPS fournissent un accès direct en tant qu'utilisateur root par défaut. Dans ce cas, nous omettons l'utilisation de sudo dans toutes les commandes. Pour confirmer l'utilisateur actuel, nous exécutons :

whoami

Si la sortie de la commande est root, sudo n'est pas requis avant les commandes suivantes :

sudo apt update && sudo apt upgrade
# Debian 12+
sudo apt install docker.io docker-compose
# Ubuntu 24.04+
sudo apt install docker.io docker-compose-v2

1.3.2 Ajout de notre utilisateur au groupe Docker

Si la sortie de la commande whoami exécutée précédemment était root, nous ignorons cette étape ; sinon, nous exécutons la commande suivante :

sudo usermod -aG docker $(whoami)

Cela nous permettra d'exécuter la commande docker sans privilèges.

1.3.3 Clonage du dépôt du projet

git clone https://github.com/cashu4community/cashu4cs-deploy.git
cd cashu4cs-deploy
Important : À partir de maintenant, toutes les commandes seront exécutées depuis le répertoire cashu4cs-deploy.

1.4 Configuration initiale

Pour pouvoir démarrer l'infrastructure, plusieurs paramètres doivent être configurés. Il est recommandé de les conserver dans un document, car ils seront nécessaires dans les sections suivantes de ce chapitre.

1.4.1 Configuration des paramètres de Lightning Network Daemon

Modification de l'IP publique du nœud Lightning

Pour obtenir l'IP publique, nous utiliserons le script get_public_ip.sh situé à la racine du répertoire cashu4cs-deploy.

./get_public_ip.sh

Cela renvoie une sortie comme la suivante :

72.61.27.142

Connaissant cette IP, nous allons éditer le fichier lnd.conf.

nano app-data/lnd/lnd.conf

Nous recherchons la ligne externalip= et ajoutons l'IP obtenue 72.61.27.142.

Image 2 : Fichier lnd.conf, paramètre externalip=.

Nous sauvegardons et quittons le fichier ctrl+s et ctrl+x.

Modification de l'alias du nœud LND

L'alias est utile pour retrouver le nœud dans les explorateurs du réseau Lightning comme mempool.space ou amber.space. Pour le modifier, nous éditons à nouveau le fichier lnd.conf et recherchons la ligne alias=. Pour ce chapitre, nous utiliserons Cashu4CS comme alias du nœud LND.

Image 3 : Fichier lnd.conf, paramètre alias=.

Création du mot de passe pour le portefeuille du nœud LND

Le processus de création du portefeuille du nœud LND que nous verrons plus tard nous demande un mot de passe utilisé pour chiffrer le portefeuille et le déverrouiller à chaque redémarrage du service. Il doit comporter au moins 12 caractères, combinant majuscules, minuscules, chiffres et caractères spéciaux (par exemple : *-+). Une fois le mot de passe créé, nous le saisissons dans le fichier walletunlock situé dans app-data/lnd/.

Pour ce tutoriel, nous utiliserons +6Mn31qVwLC- comme mot de passe du portefeuille.

nano app-data/lnd/walletunlock

Image 4 : Fichier walletunlock avec le mot de passe créé précédemment.

Nous sauvegardons et quittons le fichier ctrl+s et ctrl+x.

Note : Le fichier walletunlock nous permettra de déverrouiller automatiquement le portefeuille du nœud après un redémarrage du conteneur Docker. C'est pourquoi il contient le mot de passe.

1.4.2 Création du mot de passe pour l'accès à Lightning Terminal

Pour accéder au service Lightning Terminal (désormais appelé LIT), un mot de passe est nécessaire. Il doit avoir les mêmes exigences de complexité que celui utilisé pour le portefeuille LND. Une fois généré, nous le sauvegardons dans le fichier lit.conf situé dans app-data/lit/.

Une fois le mot de passe créé, nous éditons le fichier lit.conf.

nano app-data/lit/lit.conf

Nous recherchons la ligne uipassword= et saisissons le mot de passe. Nous utiliserons +dFskhU8d35* comme exemple pour ce tutoriel :

Image 5 : Fichier lit.conf avec le mot de passe créé pour accéder à l'interface LIT.

Nous sauvegardons et quittons le fichier ctrl+s et ctrl+x.

1.4.3 Configuration des paramètres de LNbits

Le service LNbits nécessite la clé AUTH_SECRET_KEY définie dans le fichier .env et le mot de passe de la base de données PostgreSQL pour fonctionner.

Génération de la clé AUTH_SECRET_KEY
openssl rand -hex 32

Cela nous retourne quelque chose comme ceci :

f92a03c2e12362f092b6589bde08b0433cd08f4ffe9ef894fe8e01660d18054f

Nous copions la clé et éditons le fichier .env situé dans app-data/lnbits/.

nano app-data/lnbits/.env

Nous recherchons la ligne AUTH_SECRET_KEY et collons la clé générée à l'étape précédente.

Image 6 : Fichier .env avec la clé AUTH_SECRET_KEY créée précédemment.

Nous sauvegardons et quittons le fichier ctrl+s et ctrl+x.

Création du mot de passe de la base de données PostgreSQL

Nous devons maintenant créer le mot de passe que LNbits utilisera pour se connecter à la base de données PostgreSQL. Nous le saisirons dans le fichier .env édité précédemment et dans le fichier docker-compose.yml situé à la racine du répertoire cashu4cs-deploy.

Nous éditons le fichier .env.

nano app-data/lnbits/.env

Nous recherchons la ligne LNBITS_DATABASE_URL="postgres://lnbits_user:dbpassword_@db:5432/lnbits_db" et remplaçons dbpassword_ par notre mot de passe. Nous utiliserons 3Edf56gh.*FU comme exemple.

Nous sauvegardons et quittons le fichier ctrl+s et ctrl+x.

Nous éditons maintenant le fichier docker-compose.yml.

nano docker-compose.yml

Nous recherchons le service docker db: et éditons dans la section environment: la variable POSTGRES_PASSWORD :

1.4.4 Configuration des paramètres du Mint Cashu

Pour le bon fonctionnement du Mint Cashu, nous devons générer la variable MINT_PRIVATE_KEY= et les certificats SSL utilisés pour chiffrer la connexion RPC depuis le service Orchard vers le Mint.

Création de la variable MINT_PRIVATE_KEY
openssl rand -hex 32

Cela nous retourne quelque chose comme ceci :

cf33ffb9af447b1210e052548f911ba62639a6a653f7066809bacecb7436ea4b

Comme nous l'avons fait avec AUTH_SECRET_KEY de LNbits, nous copions la clé et éditons le fichier .env situé dans app-data/cashu/.

nano app-data/cashu/.env

Nous recherchons la ligne MINT_PRIVATE_KEY= et collons la clé générée à l'étape précédente :

Image 9 : Variable MINT_PRIVATE_KEY mise à jour dans le fichier .env.

Nous sauvegardons et quittons le fichier ctrl+s et ctrl+x.

Génération des certificats SSL pour la connexion RPC

Nous allons dans le répertoire certs situé dans app-data/cashu/.

cd app-data/cashu/certs

Nous exécutons le script generate_certificates.sh.

./generate_certificates.sh

Ce script génère tous les certificats nécessaires pour la connexion RPC. Si aucune erreur ne se produit, les certificats seront dans ce répertoire.

ls .
ca_cert.pem  ca_private.pem  client_cert.pem  client_private.pem  generate_certificates.sh  server_cert.pem  server_private.pem

1.5 Gestion des Services

Commande Action
docker-compose up -d Démarre l'infrastructure complète ; télécharge les images lors de la première exécution.
docker-compose down Arrête tous les services de manière contrôlée et supprime les conteneurs.
docker-compose up --force-recreate [service] -d Reconstruit un conteneur spécifique après avoir effectué des modifications dans sa configuration.
docker-compose start [service] Démarre le conteneur.
docker-compose stop [service] Arrête un conteneur.

1.5.1 Noms des services

Voici les noms des services de l'infrastructure, informations utiles pour exécuter les commandes de démarrage, d'arrêt ou de reconstruction du tableau précédent.

  • Financiers : lnd, cashu (Mint), lnbits.
  • Gestion et Réseau : lit (Lightning Terminal), npm (Proxy Manager), tor, orchard.
  • Persistance : db (PostgreSQL), redis.

1.6 Démarrage de l'Infrastructure

Pour démarrer l'infrastructure, nous exécutons :

docker-compose up -d
