Migration de l'Infrastructure vers un autre VPS

9. Migration de l'Infrastructure vers un autre VPS

Ce chapitre décrit le processus de migration de l'infrastructure complète vers un nouveau VPS. Le processus est simple : nous arrêtons les services, compressons le répertoire de données, le copions sur le nouveau serveur et le redémarrons.

Il peut arriver à un moment donné que nous ayons besoin de déplacer l'infrastructure vers un autre fournisseur de services, ou simplement que le VPS contracté soit sur le point d'expirer et qu'il soit préférable d'en acquérir un nouveau.

9.1 Arrêter l'Infrastructure

Nous devons toujours prévenir à l'avance lorsque nous effectuons ce type de tâches, pour éviter que les utilisateurs se retrouvent au milieu d'une opération.

cd cashu4cs-deploy/
docker-compose stop

À ce stade, l'infrastructure est arrêtée et personne ne pourra utiliser les services.

Si la commande s'est terminée correctement, nous listons le contenu du répertoire :

Ce fichier compressé représente toute notre infrastructure, que nous pourrons copier sur le nouveau VPS.

Important : Nous ne devons pas oublier que le VPS de destination doit disposer des prérequis nécessaires à l'infrastructure, tels que décrits dans le chapitre Premiers Pas.

9.3 Copier et décompresser cashu4cs-deploy.tar.gz sur le nouveau VPS

Nous exécutons la commande suivante :

scp cashu4cs-deploy.tar.gz root@<IP du nouveau VPS>:/root/

Une fois la copie terminée, nous nous connectons au serveur :

ssh root@<IP du nouveau VPS>
# Après nous être connectés, nous décompressons le fichier
tar zxvf cashu4cs-deploy.tar.gz
# Nous nous déplaçons dans le répertoire
cd cashu4cs-deploy/

On pourrait se demander pourquoi nous ne démarrons pas tout depuis l'étape précédente : il y a ici un détail important. Le nouveau VPS a une adresse IP différente, il faut donc mettre à jour les enregistrements DNS de notre domaine et le paramètre externalip dans le fichier lnd.conf.

Comment obtenir l'IP du nouveau VPS ? Nous pouvons la trouver dans le panneau du fournisseur ou en utilisant le script suivant :

./get_public_ip.sh
12.45.128.56

Dans l'exemple, l'IP obtenue est 12.45.128.56 ; c'est celle que nous devons mettre à jour dans le paramètre externalip et dans les enregistrements DNS. Nous pouvons maintenant passer à l'étape suivante.

9.4 Démarrer l'infrastructure

Nous exécutons ce qui suit :

docker-compose up -d

À ce stade, les images sont téléchargées à nouveau et les conteneurs sont construits avec les données qu'ils avaient déjà, ce qui nous permettra d'avoir l'infrastructure opérationnelle en quelques minutes.
